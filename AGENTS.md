# AGENTS.md

Machine-first orientation for AI coding agents. Humans should read [README.md](README.md) instead — this file trades narrative for density.

## What this repo is

A builder for a containerized, AI-augmented Rust development environment backed by **MongoDB**. Two deliverables:

1. **Shared base Docker image** (`build_base_dev_image/`) → published to DockerHub as `tsouche/base_rust_dev`. Generic tooling only: Ubuntu 22.04, Rust stable, Node 22, Bun, Playwright+Chromium, QMD, Graphify, MongoDB shell (`mongosh`), `gh`, Docker CLI, SSH server.
2. **Deployment kit** (`deploy_dev_env/`) → project-specific Docker image + `docker-compose` + PowerShell scripts. Spins up 3 containers: `dev-container` (built `FROM tsouche/base_rust_dev`), `mongo-db` (MongoDB 7.0), `mongo-express` (web admin UI).

Sibling repo: [`dev_env_builder_postgresql`](https://github.com/tsouche/dev_env_builder_postgresql) — same architecture, PostgreSQL + Adminer instead of MongoDB + Mongo Express.

## Architecture (layered)

```
tsouche/base_rust_dev (DockerHub, shared, generic tooling)
        ↓ FROM
Dockerfile.rust-dev (this repo, project-specific: SSH keys, git identity, Claude Code CLI)
        ↓ docker-compose-dev.yml
dev-container (SSH :2222) ── mongo-db (:27017) ── mongo-express (:8080)
```

- `dev-container` is where you work: `/workspace` = bind-mounted project code, `~/.claude` = eternal bind-mounted Windows volume, per-project named volume for `/home/rustdev` (includes QMD index).
- QMD GGUF models (~2GB) are a separate shared Windows volume — downloaded once, reused by every project.
- Graphify needs no volume: code-only extraction is pure AST + graph traversal, output lives in-repo at `graphify-out/` and is meant to be committed.

## Key facts an agent needs before editing

- **Windows/PowerShell project.** Scripts are `.ps1`, run from a Windows host with Docker Desktop. Bash scripts (`init_*.sh`, `test-deployment.sh`) run *inside* the Linux containers, copied in via `docker cp` at deploy time (not baked into the image) so they self-heal on redeploy without a rebuild.
- **`/home/rustdev` is a persistent named volume.** Docker only seeds a volume's content from the image the *first* time it's created — anything added under `/home/${USERNAME}` in a later base-image build is invisible on redeploy against an existing volume. This is why QMD/Graphify/uv are installed under `/usr/local`, not the home dir. Keep new tools there too.
- **`.env` is the single source of config** — ports, DB credentials, volume paths, image tags. `01-init-db.js` and `authorized_keys` are regenerated from it by `deploy-dev.ps1` on every run.
- **Everything is idempotent by design.** `deploy-dev.ps1`, `cleanup.ps1`, and every `init_*.sh` are safe to re-run any number of times.
- **QMD vs Graphify:** QMD = content/semantic search (BM25 + vectors, per-repo SQLite index, git-ignored). Graphify = structural search (call graphs, path tracing, tree-sitter AST, zero LLM cost, output *is* committed to git). Both are configured automatically per-repo; routing rules for which to use live in `CLAUDE.md.template`.
- **Versioning:** semantic, tracked per-subdir in `CHANGELOG.md` files; current version is stamped in each README's header.
