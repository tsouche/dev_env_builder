## Locked-in design decisions (do not re-derive)

- **Additive, not a replacement** — QMD is untouched; Graphify is new and
  parallel. User confirmed explicitly.
- **No new Docker volume** — code-only extraction is pure tree-sitter +
  networkx, zero LLM cost, no GGUF models. Simpler than QMD's ~2GB model
  volume.
- **Path-based scoping, not flag-based** — Graphify operates on
  `./graphify-out/` relative to cwd, no `--index {name}` flag like QMD, so no
  per-project `graphify-{name}` aliases are needed — just `cd` into the repo.
- **Commit `graphify-out/graph.json` + `GRAPH_REPORT.md`** to each project
  repo (gitignore only `cost.json`) — upstream's own recommended workflow,
  deliberately the opposite of QMD's fully-gitignored SQLite index.
- **Install**: `uv` (astral installer) + `uv tool install "graphifyy[mcp,leiden]"`.
  No separate Python install (Ubuntu 22.04 ships 3.10, meets the `>=3.10` floor).
- **Per-repo Claude Code integration via `graphify claude install --project`**
  (writes the project's own CLAUDE.md + `.claude/skills/graphify/SKILL.md` +
  a `PreToolUse` hook) — Graphify's own official integration path, not a
  hand-rolled MCP entry.
- **No `--strict` mode** — default soft nudge coexists better with QMD's
  existing soft CLAUDE.md rule than strict mode's first-Read-blocking behavior.

## Research grounding (already done, don't redo)

Graphify's own `BENCHMARKS.md`: on ERPNext (~1M LOC), graph-expand ties/
slightly loses to dense vector RAG on QA accuracy (76%/0.844 vs 76%/0.848).
Graph's real edge is structural multi-hop questions (call graphs, path
tracing) that QMD's chunk-retrieval literally cannot answer — a query-type
difference, not a codebase-size threshold. Also: the GitHub repo shows
100k+ stars but was created 2026-04-03 (~4 months old at research time) —
treat the star count as likely inflated/bot-driven; the underlying code and
packaging are legitimate and well-built regardless.
